# Samsung UWB trial wire format

This adapter translates one constrained Apple-generated profile into the 35-byte
Samsung format. It does not establish firmware compatibility. Success requires
a real Nearby Interaction distance update from the selected accessory token.

The source is pinned [uTag UwbConfig](https://github.com/KieronQuinn/uTag/blob/f46375a9c2af6de4c8678f6aba7b91972054ae74/app/src/main/java/com/kieronquinn/app/utag/components/uwb/UwbConfig.kt)
and its LengthByteArray helper. The default packed header is `00 2f 0c 9c 05`.
Disabling hopping changes the final header byte to `01`. Earlier research notes
omitted SFD ID 2's upper bit in byte 3; `1c` was incorrect for this profile.

Offsets are zero-based. Multibyte numeric fields below use big endian.

| Offset | Size | Value |
|---|---:|---|
| 0 | 5 | Packed profile header |
| 5 | 4 | Nonzero session ID from Apple |
| 9 | 2 | Accessory address declared in the Apple bootstrap |
| 11 | 2 | Phone address generated by Apple |
| 13 | 1 | Channel 9 |
| 14 | 2 | Samsung slot field 2000 |
| 16 | 2 | Apple ranging interval in milliseconds |
| 18 | 1 | Source constant 3 |
| 19 | 1 | Apple preamble, restricted to 9–12 |
| 20 | 2 | Source constants 1, 5 |
| 22 | 2 | Apple vendor 0x004c (experimental adaptation) |
| 24 | 6 | Apple static STS IV |
| 30 | 1 | Six slots |
| 31 | 4 | Zero source constants |

Two assumptions require the physical trial: uTag pairs Android slot duration
2400 RSTU with Samsung field 2000, whose conversion is not proven here; Apple
vendor 0x004c replaces uTag's zero vendor. Other slot durations, profiles or
address collisions are rejected. Byte 18 and bytes 20–21 retain source values
without inventing their semantics. The header's hopping bit is global bit 34;
acceptance of either hopping variant by the tag remains untested.

uTag activates characteristic DEE30008 with payload 01 before writing the
configuration to DEE30009, and stops with payload 00 on DEE30008, in service
FD5A. Each write waits for its transport acknowledgement. An ATT write ACK is
not proof of radio compatibility or a distance measurement.

The supplied APK's direct generic characteristic writer encrypts these writes:
GattActionManagerImpl.Q (`classes8.dex`, code item 0x4b8244) passes true into
connector f.h. Its runnable calls u9.b.l0 (`classes5.dex`, code item 0x4fbb04),
where that boolean selects EncryptManager.b before setValue/writeCharacteristic.
Encryption uses the authenticated command key, tag nonce IV and a four-byte
little-endian outgoing counter before the payload. The counter begins at 1 and
is independent of incoming battery response counters. Writes must be serialized.
Incoming DEE30009 notifications are not interpreted as an Apple blob, status
success or distance; their unexplained contents must not enter diagnostics.

## Retrying after a trial

Requesting a Bluetooth cancellation does not mean the native connection is closed.
The adapter now keeps its selected peripheral and remains busy until CoreBluetooth
reports disconnect or connection failure. Only then can another attempt reuse that
candidate without a manual scan. Each attempt creates a delegate with a generation
token; callbacks from an older delegate cannot advance the new handshake. All five
implemented peripheral callbacks pass through that gate. Central-manager callbacks
have no attempt token: their guards use the closing barrier and manager identity.

Keys, nonces, counters and the discovered-characteristic map are cleared when close
is requested. A retry discovers characteristics again and waits for notification
subscription acknowledgements again; it does not infer readiness from a cached
isNotifying value. The cause of any firmware-specific subscription behavior remains
unproven. If closure is not acknowledged within five seconds, the old manager is
retired, candidates are cleared and the app explicitly asks for a new nearby scan.
The retry policy has deterministic lifecycle tests; repeated real-device attempts
still require owner validation.

## Response comparison and Samsung consumers (T11)

The owner observed a decrypted, frame-valid 35-byte DEE30009 payload. Its length
matches the configuration length; this alone establishes neither an echo nor
radio acceptance. The diagnostic compares that payload locally with the exact
35-byte plaintext configuration handed to the characteristic writer during the
same attempt. Only match/different/unavailable is exposed. A match means byte
equality, not that ranging started or that Apple Nearby Interaction is compatible.
No raw payload, configuration, key or nonce belongs in the diagnostic output.

The bounded APK follow-up used offline DEX decoding because the REA JADX provider
was unavailable. Evidence below is from the supplied APK's `classes8.dex`, SHA256
`582aa601197129d9489b0db9d55c493603e9544c17b7910d10d926a3aa693623`, except
the explicitly identified `classes9.dex` Binder path. Offsets after a code-item
address are instruction byte offsets within that method.

- `lg0.c.<clinit>`, code item `0x62a010`, loads the DEE30009 UUID at `+0xaa`
  and stores it in `lg0.c.h` at `+0xbc`.
- `GattActionManagerImpl.j`, `0x4b8bb0`, maps that UUID to `UWB_PARAMETER`
  at `+0x16c`–`+0x17c`. For this event and DEBUG, the wrapper parses the first
  two payload hex characters with `Integer.parseInt(String)` (decimal text,
  no radix argument), retaining the rest as `extraValue`. This is wrapper
  structure; no accepted/rejected status meaning was established.
- The same method constructs `GattControlServiceState` at `+0x282` and dispatches
  registered listeners at `+0x294`. `base.capability.g.accept`, `0x497288`,
  discriminator 1, invokes `tag.gatt.j.a(state, invocationID)` at `+0x1cc`.
- In `classes9.dex`, `smarttag.service.manager.f.a`, `0x3fc36c`, forwards the
  state through `RemoteCallbackList` to `IGattCharacteristicChangedCallback.y1`
  at `+0x32`. The Binder proxy `smarttag.service.b.y1`, `0x3f99c8`, parcels
  it without interpreting UWB parameters.
- The generic plugin notification callback
  `QcPluginServiceBLECoreDeviceImpl$registerControlServiceNotificationListener$1.onControlServiceChanged`,
  `0x558d20`, forwards `stateJson` to
  `IPluginGattControlServiceNotificationListener` at `+0x2c`; its Binder proxy
  at `0x592b5c` transmits that string. The eventual plugin consumer is unresolved.

An instruction-aware search across all 11 APK DEX files found direct reads of
the `UWB_PARAMETER` enum field only in its enum value list and the event factory.
The inspected callback implementations supplied forwarding, logging and other
feature handling, not recovered UWB session/status semantics. This search does
not cover ordinal-based dispatch, reflection or separately delivered plugins.
No actual response bytes were supplied for this research; echo contents,
firmware acceptance and distance remain unproven. A real NI distance update
remains the success condition.
